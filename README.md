# ЛР5, вариант 5 — Scatter-Gather DMA (QEMU EDU)

Файлы: `edu_dma.c` (модуль), `edu_dma.h` (ioctl-интерфейс), `test.c` (пользовательская программа), `Makefile`.

## Запуск QEMU
Адреса RAM на aarch64 `virt` начинаются с 0x40000000, а EDU по умолчанию обрезает DMA-адреса
до 28 бит (`dma_mask`). Поэтому QEMU нужно запускать так:

    -device edu,dma_mask=0xffffffffffffffff

Драйвер при загрузке делает самотест и пишет в dmesg, если маска неверна.

## Использование
    make && insmod edu_dma.ko
    ./test -m sg -d bidir -n 8 64K        # режим, направление, сегменты, размер
    ./test -m coherent|streaming|memcpy -d to|from|bidir 1M
    ./test -x ...                         # без проверки (только указанное направление)
    ./test -b                             # сравнение memcpy/DMA: 1K, 64K, 1M (16M — с -F)
    cat /proc/dmadriver                   # число передач и объём
    rmmod edu_dma

Режим sg выводит: число сегментов (исходных и после dma_map_sg), общий размер, время, результат проверки.

## Особенности EDU (для отчёта)
- Регистры DMA в реальном QEMU: SRC 0x80, DST 0x88, COUNT 0x90, CMD 0x98 (не 0x60–0x6c, как в методичке);
  0x24 — статус IRQ, 0x64 — подтверждение IRQ.
- У EDU нет дескрипторов scatter-gather и внутренний буфер 4 КиБ: одна операция — не более 4096 байт.
  Поэтому SG реализован запасным вариантом: `dma_map_sg()` + последовательные передачи с одним
  completion. Сегменты после dma_map_sg могут слиться, источник и приёмник обходятся как потоки байт.
- Каждая операция в QEMU завершается по таймеру 100 мс, итого ~40 КиБ/с на направление.
  DMA в тысячи раз медленнее memcpy — это свойство эмулятора, а не драйвера.
- Режимы memcpy/coherent/streaming/sg для двунаправленной проверки делают две передачи
  (в EDU и обратно); в -d to / -d from учитывается время только своего направления.

## Результаты (4 vCPU, загрузка CPU — по /proc/stat, 25% = одно ядро занято)
| метод | 1 КБ | 64 КБ | 1 МБ |
|---|---|---|---|
| memcpy | 0.07 мкс, ~13 ГиБ/с | 4.3 мкс, ~14.6 ГиБ/с | 66 мкс, ~15 ГиБ/с |
| coherent (bidir) | 0.26 с | 4.4 с | 76.8 с |
| streaming (bidir) | 0.26 с | 4.1 с | 67.9 с |
| sg (bidir) | 0.29 с | 4.2 с | 66.9 с |
DMA: ~0.015 МиБ/с, CPU ≈ 0.1–0.2% (процесс спит в completion). 16 МБ: sg, `-d to -x`,
128 сегментов, 4096 операций, 542 с, 0.03 МиБ/с, CPU 0.2%; memcpy 16 МБ — 1.17 мс, ~13.6 ГиБ/с.
